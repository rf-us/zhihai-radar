# 五维评分口径（可复核）

> 答辩时可把本文摊开，逐项对照验证卡上的分数。所有公式在 `internal/domain`，
> 纯函数、无 IO、无时钟（时间由 Input 传入），可用单表驱动复算。

## 权重

| 维度 | 名称 | 权重 | 数据来源 |
|---|---|---:|---|
| D1 | 需求热度 | 35% | 知乎搜索 |
| D2 | 痛点强度 | 20% | 直答 Agent + 原文链接白名单 |
| D3 | 趋势信号 | 15% | 热榜 + 全网搜索 |
| D4 | 竞争供给 | 10% | 全网搜索（反向指标：越高越不推荐） |
| D5 | 成本可行性 | 20% | BOM 成本 + 包装 + 运费 + 佣金 |

权重之和 = 1。**维度缺失时不补 0**，而是从加权中剔除该维度，并对剩余权重归一化；
`Confidence` = 实际参与计算的权重之和。这是"诚实分数"的核心：
只测了四项时 confidence = 0.8，页面显示"覆盖权重 80%"，而不是把缺的当 0 分。

## D1 需求热度

```
D1 = clamp(40·log10(1+加权点赞) + 30·log10(1+加权评论) + 3·命中条数, 0, 100)
加权系数 = 0.5 + 0.5·AuthorityLevel/4   （AuthorityLevel 0–4）
```

## D2 痛点强度

```
D2 = clamp(4 × Σ严重度, 0, 100)    严重度 1–5
```

**无原文链接的痛点不计分**（`validEvidenceURL` 做形状校验，service 层用本次检索 URL
白名单做归属校验）。这是防止模型幻觉混进分数的闸门。

## D3 趋势信号

```
D3 = 近 30 天讨论占比 × 60 + (热榜命中 ? 40 : 0)
```

首次启动可能要做数据库迁移，5s 以上属正常——热榜抓取的超时按此设置，不在 3 秒内判失败。

## D4 竞争供给（反向）

```
D4 = clamp(6 × 去重域名数 + 20 × min(1, 价格带离散度), 0, 100)
```

用**去重域名数**近似竞品数，不用结果条数——条数由请求的 Count 决定，
拿它当竞品数会让所有品类都顶格（第一版实测踩过）。

## D5 成本可行性

```
单台 BOM 成本 = Σ(单价 × 每台用量 × (1+损耗率/100))
use_mode=1 时每台用量 = 1/Qty   （"每 1000 台用 1 个" → 单价 300 得 0.3）
总成本 = BOM + 包装 + 头程运费
建议售价来源（优先级）：手工指定 → 竞品均价×0.8 → 总成本/0.6（保证 40% 毛利）
毛利 = (建议售价×(1-佣金率/100) - 总成本) / 建议售价
D5 = 毛利 ≥ 40% ? 100 : clamp(毛利/0.40×100, 0, 100)
```

**阈值常量**：毛利满分线 = 0.40（`EstimateCost`/`EstimateCostWithExtras` 内），
佣金率合法范围 0–100（`CostExtras.Validate`），负单价/负损耗率的行直接跳过。
改阈值必须同步本文与单测，否则"分数怎么来的"就答不上来。

## 综合分与结论

```
Overall = Σ(可用维度权重 × 分数) / Σ(可用维度权重)
Confidence = Σ(可用维度权重)
```

结论规则（`domain.Verdict`）：

- `Overall < 45` 或 `D4 ≥ 80` → **不建议**
- `Overall ≥ 70` 且 `D2 ≥ 50` 且 **D5 已测算** → **值得验证**
- 其余 → **需进一步验证**

**成本门禁**：未测算成本时不判"值得验证"。这是产品最容易被质疑的地方——
没有成本数据就说值得投产，等于编结论。填完成本后 confidence 从 0.8 变 1.0；
删掉成本会重算回 0.8，结论回落，不是一次性开关。
