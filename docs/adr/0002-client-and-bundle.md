# ADR 0002：交付形态改为「客户端 + 捆绑 RFERP + 报告」

- 状态：已接受（2026-11-27，方向由产品侧调整）
- 影响：取代 ADR 0001 中"只有 Web 单页"的部分，不改"独立服务 + HTTP 接口"的边界

## 背景

评委要能自己装起来、自己点完一整条链路。纯网页形态做不到两件事：

1. 无法体现"选品结论落到 ERP"是真的落库，而不是演示脚本；
2. 知乎配额只有 100 次/天，现场多人点击必然耗尽。

同时需要产出可带走的成果物（PDF 调研报告），以及把供应链选择写回 ERP。

## 决策

交付四个东西，打包成一个安装包：

```
zhihai-radar-setup.exe
├── radar 客户端（Wails，界面与 RFERP 客户端同构）
├── radar 服务（内嵌，127.0.0.1 随机端口）
├── RFERP（reef 构建，SQLite only，功能锁定）
└── 离线快照 + 示例数据
```

### 1. radar 客户端

与 RFERP 客户端同一套形态：Wails v2 + WebView2 + 内嵌 HTTP 服务（127.0.0.1 随机端口）。
理由不是"抄"，而是评委已经熟悉那个安装/启动/登录节奏，两个客户端长得一样，学习成本为零。

### 2. 捆绑的 RFERP

- 从私有 `rf-us/reef` 构建，**只发布二进制，不发布源码**；
- 只支持 SQLite（单机、免装 MySQL）；
- 用 reef 自带的构建期版本机制裁剪：`-ldflags "-X main.editionCode=..."`；
- 与 radar 无关的功能（用户管理、备份恢复、自动更新、多库切换）锁定或隐藏。

> reef 现有四个版本（制造/商贸/工贸/试用）都不等于"radar 专用"。需要新增一个版本代号，
> 或在私有分支上打一个小补丁——补丁只进二进制，不进任何公开仓库。

### 3. PDF 调研报告

- 纯 Go 生成，不依赖外部 Chrome/wkhtmltopdf（评委机器不可控）；
- 必须内嵌中文字体（Noto Sans SC，OFL），否则中文全是方块；
- 内容：候选结论、五维雷达、证据链（含原文链接）、成本构成、供应链选择、下一步假设；
- 与验证卡共用同一份数据结构，避免"网页一套、PDF 一套"。

### 4. 供应链选择 → 写回 RFERP

采纳不再只是"建产品 + 建 BOM"，而是三步：

```
选品结论 → 选供应链（供应商 + 单价 + 交期）→ 写回 RFERP
                                              ├─ 确保零件存在（POST /api/parts，带 supplier）
                                              ├─ 建产品（POST /api/products）
                                              └─ 建 BOM（POST /api/bom，逐条）
```

价格仍只留在 radar（reef 无价格字段），但**供应商**会写进 `parts.supplier`，
所以在 RFERP 里点开零件就能看到是哪家供的。

## 代价

| 代价 | 说明 |
|---|---|
| 安装包体积 | RFERP 二进制 15MB + radar 客户端 20MB，合计约 40MB |
| 版本耦合 | 捆绑的 RFERP 与 radar 的接口契约必须同版本发布，CI 要跑 live 契约测试 |
| 构建链变重 | 需要 Wails + MinGW + Node + 私有 reef 的访问权限 |
| 锁功能的维护成本 | radar 专用版本与上游 reef 有分叉，每次上游更新要重新对齐 |

## 被否决的方案

| 方案 | 否决理由 |
|---|---|
| 只给网页链接 | 评委看不到"落到 ERP"的真实性；配额也不够 |
| 让评委自己装 RFERP + radar | 两步安装、还要配设备指纹，现场必翻车 |
| 把 reef 源码放进 radar 仓库 | 私有仓库，且违反"不泄露源码" |

## 补充决策（2026-11-27，产品侧确认）

1. **锁定范围**：用户管理 / 备份恢复 / 自动更新 / 切换数据库 锁死；产品、BOM、批次、库存保留。
2. **主界面形态**：限制性问答（六道选择题），不是搜索框。题库与推导见 `internal/dialogue`，
   报告章节由 Q5「主要顾虑」触发——选了认证才生成《合规与认证》，没选就不出现。
3. **供应链做深**：多家比价（供应商 / 单价 / MOQ / 交期 / 账期），报告里出对比表并给推荐方案。
4. **安装包**：Inno Setup 真安装器。radar 以"ERP 插件"的形态随 RFERP 一起装，降低评委上手成本；
   但产品叙事里 radar 是主角——安装包首屏、快捷方式、报告落款都以 radar 为主，RFERP 标注为"随附运行环境"。
