# 知海选品雷达 · 作品提报说明

> 用途：知乎黑客松 S3 湾区共创季 · 赛道 03「AI × 出海」的作品说明计划书。
> 对应官方「产品说明计划书（必交）」要求。

---

## 1. 核心创作思路

出海卖家选品靠拍脑袋：看什么火就上什么，没有证据、没有成本测算、结论也落不了地。

知海选品雷达把这件事变成一条可追溯的验证链：

```
对话收集需求 → 知乎/全网四路取数 → 五维评分 + 证据链
   → 成本测算 → 供应链比价 → 写回 RFERP → 导出 PDF 报告
```

产品不是"另一个聊天机器人"：与选品无关的问题按设计拒答，这是边界，不是能力缺失。

## 2. 目标用户与真实痛点

- **目标用户**：国内制造 / 电商卖家，正在判断"哪些国内货值得出海"。
- **痛点**：
  1. 选品靠直觉，结论没有证据支撑；
  2. 知乎上有大量真实讨论，但没人把它结构化成决策依据；
  3. 就算看好一个品类，也算不清成本、找不到供应商，结论落不了地。

## 3. 核心体验与使用步骤

1. **对话**：一句话说清品类/市场/价格带，或按提示逐项补充；离题会被拉回。
2. **验证卡**：五维雷达图（需求热度/痛点强度/趋势信号/竞争供给/成本可行性），
   每个分数可展开看到计算依据，每条痛点挂着知乎原文链接与采集时间。
3. **成本**：填 BOM（零件、数量、单价、损耗率、计费方式），即时算单台成本、
   毛利与建议售价；未测算时明确写"未测算"，不编 0。
4. **比价**：多家供应商按目标数量比总价（含阶梯价、MOQ、交期），选定一家。
5. **落库 + 报告**：一键写回 RFERP（建产品 + 建零件并写供应商 + 建 BOM），
   导出带条件章节的 PDF 调研报告。

**报告随提问变化**：对话中提到"认证"才生成《合规与认证》，提到"物流"才生成
《物流与包装》——由槽位推导，不是模型自由发挥。

## 4. 技术实现方案

- **独立服务**：radar 是独立 Go 服务，通过公开 HTTP API 对接 RFERP，
  不复制、不修改其源码，也不直接读写其数据库。
- **双形态同一份代码**：浏览器版做体验与传播，Wails 桌面版做完整闭环
  （"写回 ERP"必须能碰到本机运行环境，浏览器做不到）。
- **五维模型**：纯函数实现，权重与算例见 `docs/scoring.md`，可在答辩时单独演示
  "分数怎么来的"。维度缺失时按可用权重归一化，置信度诚实呈现。
- **成本门禁**：未测算成本时不判"值得验证"，这是产品最容易被质疑的地方。
- **PDF**：纯 Go 渲染（gopdf + 内嵌 Noto Sans SC 子集 1.16MB），不依赖浏览器
  或 wkhtmltopdf；同一份材料两次生成一致，可复现。选型理由见 `docs/adr/0003-pdf-rendering.md`。
- **可追溯**：每条证据带 URL 与采集时间；生成报告时不重新调接口。
- **合规性**：框架使用 RFERP 作为外部依赖，核心创新（五维模型、证据链、
  知乎数据映射、报告条件章节）为团队独立形成；见 `docs/compliance.md`。

## 5. 使用的知乎开放能力与作用

| 能力 | 在作品中的作用 | 对应维度 |
|---|---|---|
| 知乎搜索 | 抓真实讨论、点赞、评论、权威度，作为需求与痛点证据 | D1 / D2 |
| 全网搜索 | 竞品站点、价格带、近期讨论分布 | D3 / D4 |
| 热榜 | 判断品类是否处在热点 | D3 |
| 直答 Agent | 总结未被满足的需求与痛点 | D2（每条痛点挂真实原文链接） |

- 四路并发取数，单次分析每个接口只调 1 次；结果缓存与请求去重。
- 热榜/直答各 100 次/天，是稀缺配额：公网 Demo 默认走离线快照，
  真实接口只在演示时手动开启；分析端点还有两级限流（单会话 1 次/分钟、
  全局 30 次/小时，429 带 Retry-After）保护配额。
- Access Secret 只从环境变量读取，不落库、不进日志、不下发前端。

## 6. 与社区生态的契合与价值

知乎沉淀了大量真实的产品讨论与多元观点。本作品把这类内容从"读一读"变成
"可复核的决策证据"：每条结论都能点回原文，分数有算例，结论能落到 ERP。
后续可与知乎出海内容场景结合，做成选品看板或社区栏目工具。

## 7. 已知限制

- 公网 Demo 为只读模式，不开放写回；完整闭环请用桌面安装包。
- 数据来自知乎开放平台与离线快照，报告标注采集时间，不承诺价格准确。
- 中文子集覆盖常用 3500 字；生僻字替换为 □ 并在报告末尾计数告警。
- 运行环境与 radar 必须同机部署（设备指纹绑定）。

## 8. 答辩常见问题

**Q：和直接用 ChatGPT 问"什么好卖"有什么区别？**
A：① 证据可回溯，每条结论挂原文链接与采集时间；② 分数可复核，权重与算例写在
`docs/scoring.md`，没测算就明说"未测算"；③ 结论能落地，选定供应商后一键写进
ERP 的产品与 BOM，不是一段文字。

**Q：数据可不可信？**
A：来自知乎开放平台四个官方接口，不是爬虫；报告每条证据带 URL 与采集时间，
且生成报告时不重新调接口——同一份材料两次生成结果一致，可复现。

**Q：为什么不做成纯网页？**
A：做了，两种形态同一份代码。但"写回 ERP"必须有本地运行环境，浏览器碰不到
本机数据库；所以网页版做体验与传播，安装包做完整闭环。
