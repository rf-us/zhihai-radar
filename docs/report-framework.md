# PDF 调研报告框架

> 报告不是"把页面截图拼起来"，而是**由限制性问答驱动的结构化文档**。
> 同一套章节模型同时服务于屏幕与 PDF，避免两处漂移。

## 1. 问答形态：开放对话 + 槽位抽取

入口是**对话**，不是问卷：用户可以用一句话把品类、市场、价格、供应链一起说完，
系统从中抽取槽位，缺什么问什么（实现见 `internal/dialogue/session.go`）。

六道题仍然保留，但只作为**兜底与规范**——用户说不清时按题引导，说得清时一句话即可。
每个槽位都直接映射到评分参数或报告章节：

| 槽位 | 抽取示例 | 影响 |

| 题 | 选项 | 影响 |
|---|---|---|---|
| 品类 | "想看看便携咖啡机" | 检索关键词 |
| 市场 | "卖到北美" | 竞品站点过滤、认证清单 |
| 价格带 | "$50 左右" | 建议售价与 D5 的毛利判定基准 |
| 供应链 | "长期代工" | 供应链方案深度（能否谈 MOQ/账期） |
| 顾虑 | "认证麻烦吗" | 报告**加开**对应章节 |
| 深度 | "要完整证据链" | 证据条数与报告详略 |

顾虑是"灵活生成"的开关：提到认证，报告就多一节《合规与认证》；提到物流，就多一节《体积重与头程》。
没提到的不生成，报告不会千篇一律。

**离题不回答**：与选品无关的输入（闲聊、写诗、问身份）一律拒答并拉回主题，
一句话即可，不展开。这不是通用聊天机器人，边界写在代码里，也有测试守着。

## 2. 章节模型

固定六节 + 至多三节条件章节：

```
1  结论摘要         结论 / 综合分 / 置信度 / 一句话理由
2  需求与痛点       D1、D2 + Top N 证据（标题、摘要、原文链接、点赞评论）
3  竞争格局         D4 + 竞品表（名称、价格带、卖点、链接）
4  成本与定价       BOM 明细、单台成本、建议售价、毛利、敏感度
5  供应链方案       多供应商对比表 + 推荐方案 + 交期/MOQ/账期
6  风险与下一步     未验证的假设、需要线下核实的三件事
A  合规与认证       [条件] 目标市场认证清单（CE/FCC/PSE…）
B  物流与包装       [条件] 体积重、头程估算、包装改良建议
C  售后与退换       [条件] 常见故障、备件策略
```

每节都有 `Source` 字段，标明数据来自哪次检索/哪条证据，答辩时能逐节回溯。

## 3. 结构定义

```go
type Document struct {
    Title    string
    Meta     Meta        // 生成时间、关键词、市场、数据来源、快照版本
    Sections []Section
}

type Section struct {
    Key      string      // summary / demand / competition / cost / supply / risk / compliance ...
    Heading  string
    Lead     string      // 一段结论性的话，先给判断再给数据
    Bullets  []string
    Table    *Table
    Evidence []EvidenceRef // 可回溯到 opportunity_evidence.id
    Conditional bool       // 是否由问答触发
}
```

## 4. 生成规则

1. **先结论后数据**：每节开头一句话给判断，后面才是支撑材料。
2. **无数据不编**：某维度缺失时写"未测算/数据不足"，并说明缺哪一路数据；
   绝不用 0 冒充真实得分。
3. **证据可回溯**：每条证据带 URL 与采集时间；PDF 里的链接保持可点击。
4. **条件章节**：只由 Q5 触发；没触发就不出现在目录里。
5. **页数与详略**：快速结论 ≈ 4 页；完整证据链 ≈ 10–14 页。

## 5. 排版约束

- 中文用内嵌 Noto Sans SC；标题 500 字重，正文 400；
- A4，页边距 18mm；表格斑马纹用 5% 灰，不描粗边框；
- 每页页脚：`知海选品雷达 · 生成于 YYYY-MM-DD · 第 N 页`；
- 首页右上角标注数据快照时间——评委最常问"这是什么时候的数据"。

## 6. 待定

- 是否附二维码指向在线验证卡（需要公网地址，等部署形态定稿）；
- 供应链对比表是否披露供应商真名（演示用样例数据，需明确标注"示例"）。
