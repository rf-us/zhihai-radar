# 合规披露

本文件用于如实说明本作品的来源、依赖与边界，配合赛事"须如实披露参考和引用情况"的要求。

## 1. 原创范围

以下内容由本团队独立设计与实现：

- 五维验证模型（需求热度 / 痛点强度 / 趋势信号 / 竞争供给 / 成本可行性）及其权重、结论规则；
- 证据链结构、痛点与原文 URL 的白名单校验（防模型编造链接）；
- `Opportunity → Product + BOM` 的语义映射与采纳 Saga（含失败回滚、超时不确定态核对）；
- 本仓库的全部源代码、界面与文档。

## 2. 外部依赖

| 依赖 | 性质 | 使用方式 |
|---|---|---|
| [RFERP](https://github.com/Wu-Wh0/RFERP) | 外部 ERP 系统 | **仅通过公开 HTTP API 调用**，不包含、不修改其源码 |
| 知乎开放能力 | 外部数据源 | 经官方 API 获取公开内容摘要与原文链接 |
| SQLite（modernc.org/sqlite） | 开源库 | Go 模块依赖 |
| React / Vite / Tailwind | 开源库 | 前端构建依赖 |

**关于 RFERP 的特别说明**：该仓库未提供 `LICENSE` 文件，因此本项目**不复制其任何源代码、
不内嵌其前端组件、不修改其数据库结构**，只在运行时通过 HTTP 接口读写数据。radar 的数据库
是独立的 SQLite 文件，删除它不会影响 RFERP 中的任何数据。

## 3. 数据使用

- 只使用知乎公开内容的标题、摘要与原文链接；
- 不抓取、不存储知乎用户个人隐私信息；
- 不绕过任何访问控制，全部经官方 API 与官方配额调用；
- Access Secret 只从环境变量读取，不落库、不进日志、不下发前端。

## 4. 创作佐证

- 本仓库的提交历史（可追溯每次改动的时间与内容）；
- `docs/adr/` 下的架构决策记录；
- 开发期间的 AI 交互记录与设计底稿由团队另行留存。

## 5. 与赛事规则的关系

- 本作品不是 RFERP 的搬运或换皮：RFERP 是既有开源项目，本作品是建立在其**接口之上**的
  独立工具，核心能力（选品验证与证据链）RFERP 不具备；
- 代码仓库的公开时间与赛事"已公开发布"口径的关系，由团队在提交前确认（见开发计划 §11.1）。
